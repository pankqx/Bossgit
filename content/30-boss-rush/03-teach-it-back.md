title: Teach it back
minutes: 20
---

The **Feynman technique**: if you cannot explain something simply, you do not understand it yet. Teaching is also the habit that turns good engineers into leads.

## The exercise

Pick five topics. For each, write (or record) a two-minute explanation for a smart person who has never used Git. No jargon without explaining it. Use one picture or analogy.

| Topic | A starting analogy |
|---|---|
| Commit | a photo of your whole desk, labelled and dated |
| Branch | a sticky note on one photo that moves forward when you take a new one |
| Staging area | packing a box before you seal it |
| Merge vs rebase | stapling pages in with a note vs rewriting your pages as if you started later |
| Remote | a shared shelf in another building; you sync by carrying boxes over |
| Reflog | the security camera footage of where HEAD has been |
| Pull request | "please check my box before it goes on the shared shelf" |
| CI | a robot that unpacks and tests every box automatically |

## Check yourself

After each explanation, ask:

1. Did I say **why** it exists, not just what it does?
2. Did I mention the **trap** (for example: "never rebase shared history")?
3. Could the listener **do something** with it tomorrow?

## Do it for real

- Answer three Git questions on Stack Overflow, GitHub Discussions or your college group.
- Pair with a friend on their first pull request.
- Write a short post about the hardest bug from the capstone.

