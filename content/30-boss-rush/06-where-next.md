You know Git and GitHub better than most working developers. Here is how to keep growing.

## Go deeper into Git

- **Pro Git** (git-scm.com/book), free: chapters 7 (Git Tools) and 10 (Git Internals) will feel like revision now.
- **Git's own source** (github.com/git/git), `Documentation/technical/`: the pack format, protocol v2, the index format. Try implementing the real binary index in minigit.
- **Git release notes**: read the highlights of each release on the GitHub Blog. Git ships a new version roughly every 3 months.
- **Rewrite minigit in Go or Rust**, or add packfile reading. Very few people have done that.

## Go deeper into GitHub

- **docs.github.com**: Actions security hardening, rulesets, GitHub Apps.
- **GitHub Skills** (skills.github.com): short hands-on courses.
- **GitHub certifications**: GitHub Foundations, Actions, Advanced Security, Administration. Useful for DevOps and platform roles.

## Use it at work, starting Monday

1. Turn on the modern defaults from module 23 on your laptop.
2. Write one atomic commit with a real message body every day.
3. Review one teammate's PR a day, using the comment labels from module 11.
4. Find one thing in your team's workflow to improve: a missing ruleset, slow CI, no CODEOWNERS. Fix it with a small PR. This is how people get noticed.

## Where Git sits in a career

Git mastery will not get you hired on its own. Strong **data structures and algorithms**, **system design**, and **shipped projects** do. But Git is in every one of those projects, every day, and the person who calmly fixes the release-day disaster is the one the team remembers. You are now that person.
